# Epics & Tasks: Build `optiland-zoo` Repository

**Goal:** Create a structured, self-documenting, and automated open-source database repository named `optiland-zoo` to house thousands of Optiland optical design JSON files. The repo must feature an automated metadata registry, an autogenerated visual gallery, and a robust CI/CD validation pipeline.

---

## Epic 1: Repository Architecture & Directory Scaffolding
**As a** contributor or consumer, 
**I want** a well-structured file system 
**so that** thousands of JSON designs can be organized logically without cluttering the root directory or lagging the GitHub UI.

### Task 1.1: Directory Setup
*   Create the following directory layout:
    *   `data/` -> Subdirectories partitioned by lens type (e.g., `data/singlets/`, `data/double-gauss/`, `data/eyepieces/`).
    *   `docs/assets/` -> Directory to hold automatically generated 2D ray-trace PNG plots.
    *   `scripts/` -> Python scripts for ingestion, extraction, and validation.
    *   `.github/workflows/` -> GitHub Actions automation configuration files.
*   Initialize an empty minified master registry file: `registry.json`.

---

## Epic 2: Automation & Data Extraction Engine
**As a** maintainer, 
**I want** a Python script that automatically extracts key optical metrics and renders lens diagrams 
**so that** I do not have to manually update metadata or tables.

### Task 2.1: Implement Registry & Image Generator (`scripts/generate_registry.py`)
*   Write a script that traverses the `data/` directory and finds all `.json` design files.
*   For each JSON file, the script must:
    1. Parse the structural data or load it natively using the `optiland` API.
    2. Extract key metrics: Design Name, Number of Elements, Effective Focal Length (EFL), F-Number (F/#), Maximum Field of View (FOV), and a performance metric (like average RMS wavefront error or Strehl ratio if available).
    3. Call `optiland`'s plotting utilities to render a clean 2D layout/ray-trace diagram. Save it as a `.png` file named after the lens inside `docs/assets/` (e.g., `docs/assets/dg_50mm_f1.8.png`).
*   Output an aggregated master file `registry.json` containing the metadata array for all valid designs.

### Task 2.2: Implement Dynamic Front-End Generator
*   Extend `scripts/generate_registry.py` to rewrite the root `README.md`.
*   The script should take the updated data and output:
    1. A **Featured Showcase Gallery**: A Markdown grid highlighting 4-6 prominent designs using their generated `docs/assets/` PNGs.
    2. A **Master Inventory Table**: Categorized or paginated sections containing Markdown tables with columns: `Design Name`, `Elements`, `EFL (mm)`, `F/#`, `Max FOV (°)`, `Performance`, `Ray Trace Layout (Link to PNG)`, and `Source (Link to JSON)`.

---

## Epic 3: CI/CD Pipeline & Quality Assurance
**As a** project maintainer, 
**I want** every Pull Request to be automatically validated and the registry to rebuild on merge 
**so that** bad data never enters the main branch and the documentation never goes out of sync.

### Task 3.1: Build GitHub Actions Workflow (`.github/workflows/pipeline.yml`)
*   **Trigger:** Runs on any Pull Request or Direct Push to the `main` branch.
*   **Job 1: Validation (Lint & Test)**
    *   Set up a Python environment and install `optiland` along with its dependencies (PyTorch, NumPy, Matplotlib, etc.).
    *   Validate that any newly added or modified JSON files are structurally sound and can successfully be initialized into an `optiland` system instance without throwing errors. Fail the build if a JSON is corrupt or unparseable.
*   **Job 2: Auto-Update Registry & README**
    *   If the validation passes and the event is a merge/push to `main`:
        1. Run `python scripts/generate_registry.py`.
        2. Detect if `registry.json`, `README.md`, or any files in `docs/assets/` have changed.
        3. If changed, automatically commit and push the updates back to `main` using a GitHub Actions bot identity.

---

## Acceptance Criteria for the AI Agent
1. **Zero Manual Redundancy:** Adding a single valid Optiland JSON to a subfolder under `data/` and pushing to `main` results in a new PNG in `docs/assets/`, an updated entry in `registry.json`, and a new row in the `README.md` markdown table entirely via automation.
2. **Error Resilience:** A malformed JSON file submitted via a PR will fail the GitHub Action check, preventing it from being merged.
3. **No UI Bloat:** The master table in the README remains well-structured and organized by category so it loads smoothly on standard desktop browsers.
